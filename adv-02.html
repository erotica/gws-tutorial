GWS 검증 시나리오 2 고급 ADV-02

Google Workspace 부가기능(Add-on) 개발 및 사이드 패널 구현

Docs 및 Sheets용 전용 부가기능을 개발하여 사이드 패널에서 기간계 데이터를 조회하고 문서 내에 연동·삽입하는 기술을 습득합니다.

대상 서비스
Google Apps Script, Google Docs, Google Sheets
필요 에디션
제한 없음 Editor 부가기능 · Workspace 부가기능 범위 차이
예상 소요
110분
난이도
상

사전 준비

  • 역량JavaScript + HTML. CardService 는 선언형 UI 라 HTML 과 사고방식이 다릅니다
  • 계정개발자 1개. 조직 배포까지 보려면 관리자 협조가 필요합니다
  • 샘플 데이터사이드바에서 조회할 더미 기간계 데이터(Sheets 또는 목 API) 1건
  • 주의Editor 부가기능과 Workspace 부가기능은 다른 물건입니다. Step 6 에서 그 차이를 직접 확인하게 됩니다

단계별 수행 전체 9단계

01

Apps Script 프로젝트를 새로 생성하고 부가기능 동작 방식, 메인 진입점, 필요한 스코프를 정의하기 위한 매니페스트(appsscript.json) 파일 환경을 설정합니다.

확인 appsscript.json 에 부가기능 매니페스트 항목이 추가되고 저장됩니다.
02

문서 열기 시 실행되는 onOpen(e) 트리거 핸들러를 작성하여 Google Docs 및 Sheets 문서 상단 커스텀 메뉴에 부가기능 실행 메뉴 항목을 등록합니다.

onOpen 은 단순 트리거라 권한이 제한됩니다. 메뉴를 만드는 정도는 되지만 외부 호출은 못 합니다.

확인 문서를 열면 상단 확장 프로그램 메뉴에 항목이 나타납니다.
03

HtmlService.createHtmlOutputFromFile()을 사용하여 사이드바 전용 UI 화면을 구축하고 DocumentApp/SpreadsheetApp의 showSidebar() 메서드로 우측 패널에 렌더링합니다.

showSidebar 는 Editor 부가기능 방식입니다. Docs·Sheets 안에서만 뜹니다.

확인 메뉴 클릭 시 우측에 사이드바가 열리고 HTML 이 렌더링됩니다.
04

문서 내 현재 커서 위치/선택 영역 텍스트 또는 셀 범위 데이터를 추출하고, 기간계 데이터와의 양방향 바인딩 및 데이터 편집·삽입을 수행하는 서버측 로직을 작성합니다.

확인 문서에서 텍스트를 선택하고 버튼을 누르면 선택한 값이 사이드바에 표시됩니다.
05

PropertiesService.getUserProperties() API를 활용하여 사용자별 개인화 설정값, 조회 조건 및 연동 API 인증 토큰을 암호화된 세션 상태로 안전하게 저장 및 로드합니다.

확인 설정을 저장한 뒤 사이드바를 다시 열면 값이 유지됩니다.
06

CardService 기반 Workspace 부가기능 카드 UI 구조를 구성하여 클래식 Editor 부가기능과 통합 구동할 수 있는 하이브리드 호환 환경을 구축합니다.

확인 CardService 카드가 Gmail·Calendar 사이드 패널에도 나타납니다. Editor 사이드바와 모양과 동작이 다릅니다.
07

개발자 테스트 배포(Test Deployment)를 생성하여 실제 Google Docs 및 Sheets 문서 상에서 사이드바 UI 패널 및 데이터 교환 인터랙션을 종합적으로 검증합니다.

테스트 배포는 배포 › 테스트 배포 로 만듭니다. 정식 게시 없이 본인 계정에서 즉시 확인할 수 있습니다.

확인 테스트 배포 후 본인 계정의 실제 문서에서 부가기능이 동작합니다.
08

요청되는 OAuth Scopes 범위를 최소 권한 원칙에 따라 최적화하고 사용자 동의(Consent) 동의 화면 내 안내 문구 및 동의 절차의 적절성을 최종 점검합니다.

확인 동의 화면에 매니페스트에 적은 범위만 나열되고 문구가 이해 가능합니다.
09

예외 처리를 위한 try/catch 표준 블록 구문과 Logger/Console logging을 체계화하여 Apps Script 대시보드의 실행 기록(Executions)을 활용한 모니터링 체계를 구축합니다.

확인 예외 발생 시 사용자에게 안내가 뜨고, 실행 기록에 스택이 남습니다.

확인 방법 최종 결과 2개

Docs 와 Sheets 양쪽에서 사이드바를 구동했을 때 문서 영역 연동이 모두 성공합니다.

저장한 사용자 설정값이 사이드바를 닫았다 다시 열어도 그대로 유지됩니다.

자주 겪는 오류

메뉴가 안 나타남
onOpen 은 문서를 열 때 실행됩니다. 이미 열려 있는 문서에서는 새로고침해야 합니다. 테스트 배포를 만들지 않았으면 부가기능 메뉴 자체가 없습니다.
onOpen 에서 외부 API 호출이 실패함
onOpen 은 단순 트리거라 권한이 제한됩니다. UrlFetchApp·MailApp 은 쓸 수 없습니다. 메뉴 항목을 눌렀을 때 실행되는 함수로 옮기면 정상 권한으로 동작합니다.
Sheets 에서 선택 영역을 못 읽음
Docs 용 API 를 그대로 쓴 경우입니다. Docs 는 DocumentApp.getActiveDocument().getSelection(), Sheets 는 SpreadsheetApp.getActiveRange() 입니다. 호스트 앱별로 분기해야 합니다.
CardService 카드가 Docs 에 안 뜸
Workspace 부가기능 카드는 Gmail·Calendar·Drive 사이드 패널에 나타납니다. Docs 편집기 사이드바와는 다른 영역입니다. 매니페스트의 addOns 구성을 확인하세요.
설정이 다른 사용자에게도 보임
PropertiesService.getScriptProperties() 를 쓴 경우입니다. 사용자별 저장은 getUserProperties() 를 써야 합니다. 이름이 비슷해 혼동하기 쉽습니다.
동의 화면 문구가 무섭게 보임
범위가 넓으면 '모든 문서 읽기·쓰기' 같은 문구가 뜹니다. documents.currentonly·spreadsheets.currentonly 처럼 현재 문서로 제한된 범위를 쓰면 문구가 크게 완화됩니다.
