GWS 검증 시나리오 2 고급 ADV-05

UrlFetchApp 기반 기간계 시스템 연동 및 Sheets 자동 적재

사내 기간계 시스템의 REST API를 연동하여 데이터를 Sheets에 주기적으로 자동 적재하고 예외 및 에러를 관리하는 통신 파이프라인을 구현합니다.

대상 서비스
Google Sheets, Google Apps Script
필요 에디션
제한 없음 전 에디션 · UrlFetchApp 일일 할당량 적용
예상 소요
100분
난이도
상

사전 준비

  • 역량REST API 와 JSON 이해. HTTP 상태 코드와 인증 헤더를 다룰 수 있어야 합니다
  • 연동 대상사내 API 의 인증 방식·엔드포인트·응답 스키마를 미리 확보합니다. 이것 없이는 시작할 수 없습니다
  • 네트워크사내 API 가 외부에서 접근 가능해야 합니다. 방화벽 안에만 있으면 Apps Script 가 도달하지 못합니다
  • 주의토큰을 코드에 하드코딩하지 마세요. Step 3 에서 분리하는 것이 이 UC 의 필수 항목입니다

단계별 수행 전체 9단계

01

연동 대상 기간계 시스템 REST API의 인증 방식(OAuth2, Bearer Token, API Key) 및 요청/응답 JSON 스키마 명세를 정밀 분석합니다.

확인 API 인증 방식·엔드포인트·응답 스키마가 문서로 정리됩니다.
02

Apps Script의 UrlFetchApp.fetch()를 활용하여 HTTP 요청을 전송하고, HTTP 응답 상태 코드(200 OK) 및 JSON 페이로드를 수신합니다.

UrlFetchApp.fetch 는 기본적으로 4xx·5xx 에서 예외를 던집니다. 응답 코드를 직접 보려면 muteHttpExceptions 가 필요합니다.

확인 fetch 응답 코드가 200 이고 본문이 예상 JSON 구조입니다.
03

인증 자격 증명 및 sensitive 키 정보를 PropertiesService.getScriptProperties()에 보관하여 소스 코드 내 하드코딩을 방지하고 보안성을 확보합니다.

확인 코드에 토큰 문자열이 하나도 없고, 스크립트 속성에서 읽어 씁니다.
04

수신한 JSON 데이터를 JSON.parse()로 해석한 후 Google Sheets에 매핑하기에 적합한 2차원 배열 구조로 데이터 변환 및 가공을 진행합니다.

확인 필요한 필드만 추출되어 배열로 만들어집니다.
05

Range.setValues() API를 사용하여 정제된 2차원 배열 전체 데이터를 Sheets에 단일 일괄 쓰기로 기록함으로써 API 통신 및 스크립트 실행 효율을 극대화합니다.

셀 단위로 쓰면 100배 느립니다. 2차원 배열을 만들어 setValues 로 한 번에 써야 합니다.

확인 setValues 한 번으로 전체 행이 기록되고, 셀 단위 쓰기 대비 실행 시간이 크게 줄어듭니다.
06

이전 동기화 성공 타임스탬프를 저장 및 비교하여 마지막 실행 이후 변경되거나 추가된 레코드만 선별 추출하는 증분(Incremental) 적재 로직을 구현합니다.

확인 마지막 동기화 시각이 저장되고, 다음 실행에서 변경분만 조회합니다.
07

UrlFetchApp 옵션에 muteHttpExceptions: true를 지정하여 네트워크 예외 발생 시 스크립트 중단을 막고, 지수 백오프(Exponential Backoff) 재시도 로직을 구현합니다.

일시적 실패는 재시도로 대부분 해결됩니다. 다만 지수 백오프 없이 즉시 재시도하면 상대 시스템을 더 밀어붙입니다.

확인 5xx 응답 시 재시도가 발생하고 대기 시간이 점점 길어집니다.
08

API 호출 오류 발생 시 장애 상세 트레이스 로그를 감사용 시트에 기록하고 GmailApp을 통해 시스템 관리자에게 에러 메시지를 자동 발송하도록 설정합니다.

확인 실패 건이 오류 로그 시트에 남고 담당자에게 메일이 갑니다.
09

ScriptApp 스케줄 트리거를 활성화하여 1시간 간격으로 연동 프로세스가 자동 수행되도록 배치 자동화 파이프라인을 가동합니다.

확인 1시간 주기 트리거가 등록되고 실행 기록에 정기 실행이 쌓입니다.

확인 방법 최종 결과 2개

24시간 연속 가동한 적재 건수가 원천 시스템과 100% 일치해 누락이 0건입니다.

실행 기록에서 연동 실패율과 평균 실행 시간을 산출할 수 있습니다.

자주 겪는 오류

사내 API 에 연결되지 않음
Apps Script 는 Google 서버에서 실행됩니다. 사내망 안에만 있는 API 에는 도달할 수 없습니다. 외부 공개 엔드포인트나 프록시가 필요하며, 이는 네트워크 담당 부서와 협의할 사안입니다.
404 나 401 에서 스크립트가 죽음
muteHttpExceptions: true 를 넣지 않았습니다. 기본 동작이 예외를 던지는 것이라, 응답 코드로 분기하려면 반드시 켜야 합니다.
1,000행 쓰는 데 6분이 넘음
appendRow 를 반복한 경우입니다. 2차원 배열을 만들어 setValues 한 번으로 쓰면 수 초로 줄어듭니다. Apps Script 성능 문제의 대부분이 여기서 나옵니다.
일일 할당량 초과 오류
UrlFetchApp 호출 수에 일일 한도가 있습니다. 증분 적재로 호출을 줄이고, 여러 건을 한 요청으로 묶을 수 있는지 API 쪽을 확인하세요.
증분 적재인데 중복이 쌓임
마지막 동기화 시각을 적재 성공 후에 갱신해야 합니다. 조회 직후 갱신하면 실패한 구간이 유실되고, 갱신을 빼먹으면 중복이 쌓입니다.
토큰이 만료되어 새벽에 멈춤
만료 감지와 갱신 로직이 필요합니다. 401 을 받으면 토큰을 재발급해 속성에 저장하고 재시도하는 흐름을 넣으세요. 실패 알림도 함께 걸어야 다음 날 아침에 압니다.
