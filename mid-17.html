GWS 검증 시나리오 2 중급 MID-17

Forms, Sheets, Gmail 연동을 통한 워크코드 방식의 신청·승인 워크플로 자동화

비품 구매, 교육 신청, 출입 요청 등 사내 신청서의 접수부터 담당자 승인, 결과 회신까지 전 과정을 최소한의 코딩만으로 자동화 워크플로로 구축할 수 있는지 확인해 보세요.

대상 서비스
Google Forms, Google Apps Script, Gmail
필요 에디션
제한 없음 Apps Script 는 전 에디션
예상 소요
75분
난이도
상

사전 준비

  • 계정신청자 2개 + 승인자 1개. 전 구간 확인에는 최소 3개 계정이 필요합니다
  • 권한Apps Script 사용 허용 + MailApp 발송 권한. 최초 실행 시 OAuth 동의가 필요합니다
  • 샘플 데이터신청서 항목 5개 내외 (신청 유형·수량·사유·희망일). 테스트 신청 5건 준비
  • 주의단순 트리거(onEdit)로는 메일을 보낼 수 없습니다. 반드시 설치형 트리거로 등록해야 합니다

단계별 수행 전체 9단계

01

Google Forms로 비품이나 연수 신청 양식을 만들고, '설정'에서 제출자의 이메일 주소가 자동으로 수집되도록 체크해 두세요.

02

설문 응답을 모아볼 Google Sheets를 연동해 생성한 다음, 데이터 오른쪽에 '승인 상태', '승인자', '처리 일시' 열을 새로 만들어 줍니다.

Forms 응답 시트에 열을 추가할 때는 응답 열 오른쪽에 만듭니다. 응답 열 사이에 끼우면 새 응답이 들어올 때 밀려 어긋납니다.

03

연결된 Sheets 상단 메뉴의 '확장 프로그램' > 'Apps Script'를 열어 자동화 스크립트를 작성합니다.

04

폼 제출 이벤트(onFormSubmit)가 일어날 때 작동하는 코드를 작성하세요. 누군가 신청서를 제출하면 승인 담당자에게 메일이 자동으로 보내집니다.

05

승인자에게 가는 메일 본문에 신청 요약 내용과 함께, 승인을 처리할 수 있는 시트의 주소(URL)를 링크로 쏙 넣어주세요.

06

승인용 시트 열에 '데이터 확인' 드롭다운을 걸어서, 승인자가 클릭 한 번으로 '승인' 또는 '반려'를 편하게 선택하게 만들어 줍니다.

승인/반려 드롭다운은 데이터 확인 규칙으로 만듭니다. 자유 입력으로 두면 오탈자 때문에 트리거 조건이 안 걸립니다.

07

Apps Script 좌측 트리거 메뉴에서 설치형 수정 트리거(Installable onEdit Trigger)를 생성하여 상태값 변경 시 신청자에게 회신 메일이 발송되도록 구성합니다.

08

승인 담당자 이메일 주소를 코드 안에 직접 적지 말고 Apps Script의 '스크립트 속성'에 보관하세요. 나중에 담당자가 바뀌어도 수정하기 정말 쉬워집니다.

09

Apps Script 실행 로그를 살피며 에러 예외 처리 구문(try-catch)을 보완해 주세요. 네트워크 장애가 생겨도 메일이 재발송되도록 안전장치를 만들어 줍니다.

확인 방법 최종 결과 2개

실제 테스트 신청서 5건을 제출해 보세요. 신청 접수 알림부터 승인 처리 및 결과 회신 메일까지 사람의 개입 없이 자동 진행되는지 확인합니다.

제출했던 5건 모두 중간에 누락되는 것 없이 신청자 메일함으로 결과 회신이 100% 잘 도착하는지 체크해 보세요.

자주 겪는 오류

상태를 바꿔도 회신 메일이 안 감
단순 트리거 문제입니다. 함수명을 onEdit 으로 두면 Google 이 단순 트리거로 실행해 메일 발송 권한을 주지 않습니다. 함수명을 onStatusChange 등으로 바꾸고 트리거 메뉴에서 설치형 수정 트리거로 등록하세요.
양식 제출 알림이 안 옴
제출 트리거가 스프레드시트에서 › 양식 제출 시 로 등록되어야 합니다. 폼 자체의 알림 설정과는 별개입니다. 실행 기록에서 트리거가 발화했는지 먼저 확인합니다.
새 응답이 들어오니 열이 밀림
추가 열을 Forms 응답 열 사이에 만든 경우입니다. 반드시 응답 열 오른쪽에 두어야 합니다. 이미 밀렸다면 열을 옮기고 기존 데이터를 수동으로 맞춰야 합니다.
트리거가 조건과 무관하게 계속 실행됨
onEdit 은 어느 셀을 고쳐도 실행됩니다. 함수 안에서 e.range 로 열·시트를 검사해 대상이 아닐 때 즉시 return 해야 합니다.
승인자를 바꿔야 하는데 코드를 못 고침
Step 8 을 건너뛴 경우입니다. 프로젝트 설정 › 스크립트 속성에 승인자 주소를 저장하고 코드에서 읽어 쓰면, 담당자 변경 시 속성 값만 바꾸면 됩니다.
실행 기록에 아무것도 없음
트리거가 등록되지 않았거나 다른 계정으로 만들어졌습니다. 트리거는 등록한 사람의 권한으로 실행되므로, 퇴사자가 만든 트리거는 계정 정지와 함께 멈춥니다.
