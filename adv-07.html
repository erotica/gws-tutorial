GWS 검증 시나리오 2 고급 ADV-07

GmailApp 기반 대량 메일 자동 처리 및 첨부파일 아카이빙

수신 메일을 규칙에 따라 자동 라벨링·분류하고, 첨부파일을 지정된 Google Drive 폴더로 안전하게 추출·아카이빙하는 스크립트를 구현합니다.

대상 서비스
Gmail, Google Drive, Google Apps Script
필요 에디션
제한 없음 Gmail·Drive 일일 할당량 적용
예상 소요
110분
난이도
상

사전 준비

  • 역량JavaScript + Gmail 검색 연산자. 쿼리 설계가 이 UC 의 절반입니다
  • 샘플 데이터첨부가 있는 정형 메일 1,000건 이상. 없으면 스크립트로 더미 발송해 만들어야 합니다
  • 용량첨부 1,000건이 Drive 에 쌓입니다. 용량과 파일 수 한도를 미리 확인하세요
  • 주의할당량이 이 UC 의 실질적 상한입니다. Gmail 읽기와 Drive 쓰기 모두 일일 한도가 있습니다

단계별 수행 전체 9단계

01

타깃 메일만 정밀하게 추출할 수 있도록 Gmail 검색 연산자(label:, has:attachment, filename: 등) 기반의 고급 쿼리 매개변수를 설계합니다.

쿼리가 정확할수록 처리량이 줄어듭니다. has:attachment newer_than:7d -label:처리완료 처럼 이미 처리한 것을 제외하는 조건이 중요합니다.

확인 쿼리 결과 건수가 예상 범위이고, 이미 처리한 스레드가 제외됩니다.
02

GmailApp.search() 메서드를 통해 조건에 일치하는 스레드를 가져오고, 메모리 초과를 방지하기 위해 페이징(Pagination) 방식 분할 처리를 구현합니다.

GmailApp.search 는 한 번에 가져올 수 있는 스레드 수에 제한이 있습니다. start·max 로 페이지 단위 처리가 필요합니다.

확인 페이지 단위로 스레드를 가져오며, 마지막 페이지에서 빈 배열이 반환됩니다.
03

스레드 내 개별 메시지를 순회하면서 발신자, 제목, 수신 시각 및 본문 텍스트 메타데이터를 파싱하여 추출합니다.

확인 발신자·제목·수신일시가 정확히 추출됩니다.
04

GmailMessage.getAttachments()를 호출하여 파일 Blob 데이터를 추출하고 DriveApp을 사용해 미리 지정된 구글 드라이브 아카이브 폴더에 저장합니다.

확인 첨부가 Drive 의 규칙 폴더에 저장되고 파일 크기가 원본과 같습니다.
05

동일 파일명 중복을 방지하기 위하여 메일 수신 시각 타임스탬프나 해시값을 파일명 접두사로 결합하는 명명 규칙(Naming Convention)을 적용합니다.

같은 이름의 첨부가 흔합니다(견적서.pdf). 그대로 저장하면 Drive 에 동명 파일이 쌓여 나중에 구분이 안 됩니다.

확인 동일 파일명이 있어도 덮어써지지 않고 접미사가 붙어 저장됩니다.
06

처리가 완료된 스레드에는 GmailApp.createLabel()로 생성한 처리완료 라벨을 부여하고, Inbox 수신함에서 보관(Archive) 처리하여 중복 처리를 방지합니다.

확인 처리 완료 스레드에 라벨이 붙고 받은편지함에서 사라집니다.
07

수신 및 첨부파일 보관 내역을 관리용 Google Sheets에 데이터 행으로 적재하여 모니터링 및 미처리 건에 대한 재처리 기반을 마련합니다.

확인 로그 시트에 처리 결과가 적재되어 재처리 대상을 식별할 수 있습니다.
08

Gmail 읽기 서비스 및 Drive 파일 생성의 일일 API 할당량을 고려하여 1회 스크립트 실행당 안전 처리 건수 제한을 적용합니다.

확인 배치 크기가 일일 할당량 안에서 산정되고, 실행 로그에 처리 건수가 남습니다.
09

시간 기반 스케줄 트리거를 등록하여 주기적으로 자동 아카이빙 파이프라인이 구동되도록 배치하고 작업 예외 발생 시 담당자 메일 알림을 연결합니다.

확인 야간 트리거가 등록되고 실패 시 알림이 발송됩니다.

확인 방법 최종 결과 2개

메일 1,000건을 처리했을 때 첨부파일이 누락 없이 모두 Drive 에 저장됩니다.

처리한 메일에 완료 라벨이 빠짐없이 부여되어 로그 시트 건수와 일치합니다.

자주 겪는 오류

같은 메일이 계속 다시 처리됨
쿼리에 -label:처리완료 같은 제외 조건이 없기 때문입니다. 라벨을 붙이는 것만으로는 부족하고, 쿼리에서 걸러 내야 합니다.
검색 결과가 일부만 나옴
GmailApp.search(query) 는 기본 반환 수에 제한이 있습니다. search(query, start, max) 로 페이지를 넘겨 가며 빈 배열이 올 때까지 반복해야 합니다.
Drive 에 같은 이름 파일이 잔뜩 쌓임
Drive 는 동명 파일을 허용합니다. 덮어쓰기는 안 되지만 구분이 불가능해집니다. 수신일시·발신자를 파일명에 넣어 유일하게 만드세요.
할당량 초과로 중단됨
Drive 파일 생성 한도가 대개 먼저 걸립니다. 배치 크기를 한도의 70~80% 로 낮추고 야간 트리거로 며칠에 나눠 처리하세요. 초과 시 그날은 더 이상 실행되지 않습니다.
첨부가 0바이트로 저장됨
인라인 이미지나 서명 이미지를 첨부로 잡은 경우입니다. att.getSize() 로 걸러 내고, getContentType() 으로 대상 형식만 저장하세요.
라벨은 붙었는데 받은편지함에 남아 있음
라벨 부여와 보관 처리는 별개입니다. thread.addLabel(label) 뒤에 thread.moveToArchive() 를 함께 호출해야 받은편지함에서 사라집니다.
