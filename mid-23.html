GWS 검증 시나리오 2 중급 MID-23

Chat 인커밍 웹훅을 활용한 사내 기간계 및 모니터링 시스템 알림 자동화

사내 주요 시스템이나 모니터링 알림을 Chat 메신저 스페이스로 자동 수신되도록 설정하여, 담당자들이 이슈 발생 시 실시간으로 신속하게 대응할 수 있는지 확인해 보세요.

대상 서비스
Google Chat, Google Apps Script
필요 에디션
제한 없음 웹훅은 Business Standard 이상
예상 소요
70분
난이도
상

사전 준비

  • 계정스페이스 관리자 1개 + 대응 담당자 2개
  • 에디션Incoming Webhook 은 Business Standard 이상입니다. Starter 에서는 앱 및 통합 메뉴에 웹훅 항목이 없습니다
  • 권한관리 콘솔에서 Chat 앱·웹훅이 허용되어야 합니다. 차단 시 생성 버튼이 비활성입니다
  • 주의웹훅 URL 은 그 자체가 인증 수단입니다. URL 을 아는 누구나 메시지를 보낼 수 있으므로 코드에 하드코딩하면 안 됩니다

단계별 수행 전체 9단계

01

시스템 모니터링 알림을 받아볼 전용 Google Chat 스페이스를 만들고, 빠르게 대응해 줄 담당자들을 초대하세요.

02

스페이스 제목 옆 메뉴를 선택하고 '앱 및 통합' > '웹훅'으로 이동해 '수신 웹훅 추가'를 눌러 웹훅 URL을 생성하세요.

03

발급된 Webhook URL 주소를 잘 복사해 두세요. 보안을 위해 타인에게 노출되지 않도록 안전한 스크립트 속성에 잘 보관해 줍니다.

04

Apps Script의 UrlFetchApp 서비스를 사용해 단순 text 구조의 JSON Payload를 POST 방식으로 웹훅 URL에 전송해 보세요.

UrlFetchApp.fetch(webhookUrl, {method: 'post', contentType: 'application/json', payload: JSON.stringify({text: '메시지'})}) 처럼 method·contentType·payload 세 옵션만 채우면 가장 단순한 text 알림이 나갑니다. 응답 코드 200 을 확인한 뒤에 카드로 넘어갑니다.

05

카드 메시지(cardsV2) JSON 양식을 활용해 보세요. 제목, 상세 내용, 강조 색상, 이동 버튼이 포함된 가독성 뛰어난 알림 창이 완성됩니다.

payload 를 {"cardsV2": [{"cardId": "alert", "card": {"header": {...}, "sections": [...]}}]} 형태로 바꾸면 카드가 됩니다. 버튼의 onClick.openLink.url 에 대시보드 링크를 넣으면 담당자가 알림에서 바로 이동할 수 있습니다.

06

요청 JSON에 threadKey 파라미터를 추가해 보세요. 같은 이슈나 장애 관련 후속 알림들이 답글 스레드로 보기 좋게 모이게 됩니다.

payload 최상위에 "threadKey": "issue-1234" 처럼 이슈 ID 를 값으로 넣으면, 같은 threadKey 를 쓰는 이후 알림이 새 메시지가 아니라 답글로 쌓입니다. 지정하지 않으면 알림마다 새 메시지가 되어 스페이스가 지저분해집니다.

07

Google Sheets에 특정 데이터 변화가 생길 때 Apps Script가 웹훅을 호출하여 Chat 스페이스로 알림을 자동 전송하도록 연결해 보세요.

감시 대상 Sheets 에 컨테이너 바인딩 스크립트를 붙이고 설치형 onEdit(e) 트리거를 등록합니다. e.range 로 바뀐 셀의 열·값을 검사해 조건에 맞을 때만 Step 4 의 발송 함수를 호출해야, 무관한 수정에도 알림이 울리지 않습니다.

08

이슈의 심각도(Log level)에 따라 나가는 스페이스를 다르게 하거나, 긴급 상황 시에만 @all 멘션이 포함되도록 알뜰하게 코드를 짜보세요.

심각도 값(CRITICAL·WARNING·INFO)마다 웹훅 URL 을 다른 스크립트 속성 키(WEBHOOK_URL_CRIT, WEBHOOK_URL_INFO)로 나눠 두면 발송 스페이스 분기가 쉬워집니다. CRITICAL 일 때만 카드 텍스트 앞에 <users/all> 을 붙이면 전체 멘션이 됩니다.

09

네트워크 전송 오류가 발생했을 때 에러 내용을 기록하고, 자동으로 재시도(Retry)하는 구문을 작성해 알림이 누락되지 않게 보완합니다.

UrlFetchApp.fetch 호출을 try...catch 로 감싸고, 실패하면 Utilities.sleep() 으로 대기한 뒤 최대 3회까지 재시도합니다. 재시도까지 실패한 건은 Sheets 로그 시트에 시각·오류 메시지를 남겨야 나중에 놓친 알림을 찾을 수 있습니다.

확인 방법 최종 결과 1개

실제 이벤트 10건을 발생시켰을 때 알림 도달률과 평균 전달 지연 시간이 산출되고, 지연이 대응 가능한 범위 안에 들어옵니다.

자주 겪는 오류

앱 및 통합에 웹훅 항목이 없음
Business Starter 이거나 관리 콘솔에서 Chat 앱이 차단된 상태입니다. 또한 스페이스 관리자만 웹훅을 만들 수 있습니다. 에디션 미지원이면 해당없음 판정입니다.
웹훅 URL 을 잃어버림
URL 전체는 생성 직후 한 번만 표시됩니다. 분실하면 기존 웹훅을 삭제하고 새로 만들어야 하며, 기존 URL 을 쓰던 코드도 전부 갱신해야 합니다.
POST 했는데 400 오류
contentType 을 application/json 으로 지정했는지, 페이로드를 JSON.stringify 로 문자열화했는지 확인합니다. 객체를 그대로 넣으면 폼 인코딩으로 전송되어 실패합니다.
카드가 텍스트로만 보임
cardsV2 스키마가 어긋난 경우입니다. 필수 필드(cardId, card.sections)가 빠지면 무시됩니다. 단순 text 발송부터 성공시킨 뒤 단계적으로 카드를 붙이세요.
알림이 스레드로 안 묶임
URL 에 &messageReplyOption=REPLY_MESSAGE_FALLBACK_TO_NEW_THREAD 를 붙이고 페이로드에 thread.threadKey 를 지정해야 합니다. 둘 중 하나만 있으면 새 메시지로 생성됩니다.
URL 이 코드에 그대로 들어가 있음
보안 문제입니다. 웹훅 URL 은 그 자체가 인증 수단이라 소스에 남으면 안 됩니다. 스크립트 속성에 저장하고 코드에서 읽어 쓰며, 저장소에 커밋되지 않도록 관리합니다.
