GWS 검증 시나리오 2 고급 ADV-09

Google AppSheet 고급 앱: 다중 테이블 참조·자동화 봇·보안 필터 구현

다중 테이블 간 참조 관계 설정, 가상 컬럼 및 표현식 활용, 행 수준 Security Filter, Automation Bot을 통합 적용한 업무용 노코드 앱을 구축합니다.

대상 서비스
Google AppSheet, Google Sheets
필요 에디션
AppSheet Core 이상 메일·스케줄 봇은 유료 구독 필요
예상 소요
120분
난이도
상

사전 준비

  • 라이선스Enterprise Standard·Plus 에는 AppSheet Core 포함. Business 계열은 별도 구독이 필요할 수 있습니다
  • 계정앱 제작자 1개 + 역할이 서로 다른 사용자 3개. 보안 필터 검증에 반드시 필요합니다
  • 샘플 데이터마스터(거래처) + 트랜잭션(주문) 2개 시트. 키 컬럼이 유일해야 Ref 가 성립합니다
  • 주의보안 필터와 뷰 필터는 다릅니다. 뷰 필터는 화면만 가릴 뿐 데이터는 기기로 내려갑니다

단계별 수행 전체 9단계

01

Google Sheets에 마스터 테이블과 트랜잭션 테이블을 구성하여 데이터 모델링을 수행하고 고유 키(Key) 및 기본 컬럼 속성을 정의합니다.

확인 마스터·트랜잭션 시트가 분리되고 각각 키 컬럼이 유일합니다.
02

AppSheet 에디터에서 연결 시트를 데이터 소스로 추가하고 관련 컬럼의 타입을 Ref로 설정하여 다중 테이블 간 참조 관계를 생성합니다.

Ref 관계는 자식 테이블의 열을 부모 테이블 참조로 지정해 만듭니다. 부모 쪽에는 역참조가 자동 생성됩니다.

확인 Ref 설정 후 자식 레코드에서 부모를 드롭다운으로 선택할 수 있고, 부모에 역참조 열이 자동 생성됩니다.
03

부모-자식 관계 테이블에 대해 IsPartOf 옵션을 활성화하여 부모 레코드 입력 폼 화면 내에서 자식 항목들을 인라인(Inline)으로 동시 편집 가능하도록 설정합니다.

확인 부모 상세 화면에 자식 레코드가 인라인 목록으로 함께 표시됩니다.
04

Virtual Column(가상 컬럼)을 생성하고 AppSheet 표현식(SUM, COUNT, SELECT 등)을 적용하여 자식 레코드 데이터의 실시간 집계 및 연산을 수행합니다.

확인 가상 컬럼에 집계 값이 계산되어 나타납니다. 원본 시트에는 열이 추가되지 않습니다.
05

Show_If, Editable_If, Valid_If 조건을 설계하여 사용자 권한 및 데이터 상태값 변화에 따른 필드 노출, 수정 권한, 입력 유효성을 동적으로 제어합니다.

확인 상태에 따라 필드가 숨겨지거나 읽기 전용으로 바뀝니다.
06

Security Filter 기능에 USEREMAIL() 표현식을 적용하여 앱 접속자 본인 및 본인 소속 그룹에 해당하는 레코드만 모바일 클라이언트로 다운로드되도록 행 수준 보안을 강화합니다.

보안 필터가 이 UC 의 핵심입니다. 서버에서 걸러 내려보내므로 기기에 다른 사람 데이터가 아예 저장되지 않습니다.

확인 다른 역할 계정으로 접속하면 담당 데이터만 조회됩니다. 동기화 데이터에도 포함되지 않습니다.
07

AppSheet Automation Bot을 생성하여 데이터 생성/수정/삭제 이벤트(Data Change Event) 발생 시 작동할 자동화 프로세스를 구성합니다.

봇은 이벤트 + 프로세스 구조입니다. 데이터 변경 이벤트에 태스크 묶음을 연결합니다.

확인 데이터 변경 시 봇이 실행되고 실행 이력(Monitor)에 기록됩니다.
08

봇 태스크에 이메일 자동 알림, Google Chat 메시지 전송 및 Docs/PDF 템플릿 기반 리포트 자동 생성 렌더링 작업을 연결합니다.

확인 메일·Chat 알림이 발송되고 PDF 가 생성됩니다. 유료 구독이 없으면 메일 발송이 실패합니다.
09

Schedule Event 기반의 봇을 추가하여 지정된 주기(일/주 단위)마다 정기 업무 보고 데이터를 자동 집계하고 담당자에게 리포트를 발송합니다.

확인 스케줄 봇이 등록되고 지정 시각에 실행됩니다.

확인 방법 최종 결과 2개

권한이 다른 계정 3개로 접속하면 각 계정이 자기 담당 범위의 데이터만 보게 되어 격리가 유지됩니다.

자동화 봇 실행 이력이 모두 성공으로 남습니다.

자주 겪는 오류

Ref 드롭다운에 값이 안 나옴
참조 대상 테이블이 앱에 추가되지 않았거나 키 컬럼이 유일하지 않은 경우입니다. 키가 중복되면 Ref 가 성립하지 않습니다.
인라인 뷰가 안 보임
부모 테이블의 Related … 가상 열이 상세 뷰에 포함되지 않은 것입니다. UX › Views 에서 해당 열을 표시하도록 설정하세요.
다른 담당자 데이터가 보임
뷰 필터로 처리한 경우입니다. 뷰 필터는 화면만 가리고 데이터는 기기에 내려갑니다. Security Filters 로 옮겨야 실제로 격리됩니다.
보안 필터를 걸었는데 제작자에게는 전부 보임
정상입니다. 앱 소유자·편집자는 필터가 적용되지 않습니다. 반드시 일반 사용자 계정으로 접속해 확인해야 합니다.
봇이 실행은 되는데 메일이 안 감
이메일 발송과 스케줄 이벤트 봇은 유료 구독 기능입니다. 실행 이력에는 성공으로 남아도 메일이 나가지 않습니다. 판정 시 제약으로 명시해야 합니다.
가상 컬럼 때문에 앱이 느림
가상 컬럼은 동기화할 때마다 전부 재계산됩니다. 행이 많으면 부담이 큽니다. 자주 안 바뀌는 값은 실제 열로 만들고 봇으로 갱신하는 편이 빠릅니다.
