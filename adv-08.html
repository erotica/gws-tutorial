GWS 검증 시나리오 2 고급 ADV-08

clasp·Git 기반 Apps Script 형상관리 및 CI/CD 배포 자동화

로컬 환경에서 Apps Script 코드를 개발 및 Git으로 버전 관리하고, GitHub Actions와 clasp를 연동하여 배포를 자동화하는 CI/CD 환경을 구축합니다.

대상 서비스
Google Apps Script
필요 에디션
제한 없음 Apps Script API 사용 설정 필요 · GitHub 별도
예상 소요
120분
난이도
상

사전 준비

  • 역량Git 기본(브랜치·머지·시크릿)과 CLI. GitHub Actions 문법을 읽을 수 있어야 합니다
  • 환경Node.js LTS 설치. npm i -g @google/clasp 로 전역 설치합니다
  • 권한Apps Script API 를 사용자 설정에서 켜야 합니다. 끄면 clasp 가 아무것도 못 합니다
  • 저장소GitHub 저장소 1개(비공개 권장). 인증 정보를 시크릿으로 넣습니다

단계별 수행 전체 9단계

01

개발자 로컬 환경에 Node.js 환경을 구축하고 npm을 이용하여 Google 공식 Apps Script CLI 도구인 @google/clasp 패키지를 설치합니다.

확인 clasp -v 가 버전을 출력합니다.
02

clasp login 명령어를 구동하여 Google 계정 OAuth 인증을 진행하고, 구글 계정 설정에서 Apps Script API 가동 옵션을 활성화합니다.

확인 clasp login 이 성공하고 clasp list 로 프로젝트 목록이 조회됩니다. 403 이면 API 설정 문제입니다.
03

clasp clone <scriptId> 명령어를 통해 원격에 작성된 Apps Script 프로젝트 파일들을 로컬 개발 디렉터리로 다운로드 및 동기화합니다.

확인 로컬에 .gs·.html 파일과 appsscript.json 이 내려받아집니다.
04

.clasp.json 설정 파일의 rootDir 경로를 지정하고, TypeScript/JavaScript 개발을 위한 소스 코드 모듈화 디렉터리 구조를 체계화합니다.

.clasp.json 에 스크립트 ID 와 rootDir 가 들어갑니다. 이 파일은 저장소에 커밋하되 인증 정보는 절대 넣지 않습니다.

확인 .clasp.json 에 scriptId 와 rootDir 가 있고, 소스가 지정 디렉터리에 정리됩니다.
05

Git 버전 관리 저장소를 생성(git init)하고, main(운영) 및 develop(개발) 브랜치 운영 브랜칭 전략을 수립합니다.

확인 Git 저장소가 초기화되고 브랜치 전략대로 분기됩니다.
06

로컬 IDE(VS Code 등)에서 코드를 수정 및 개발하고, clasp push 명령을 이용하여 원격 Apps Script 개발 서버로 소스를 업로드 반영합니다.

확인 clasp push 후 편집기에 변경이 반영되고 clasp open 으로 확인됩니다.
07

clasp version 및 clasp deploy 명령어를 사용하여 배포 스냅샷 버전 번호를 생성하고 개발/운영 환경별 배포 상태를 분리 관리합니다.

clasp version 은 스냅숏, clasp deploy 는 배포입니다. 버전을 만들지 않고 배포하면 롤백할 대상이 없습니다.

확인 clasp version 으로 스냅숏이 생기고, clasp deploy 로 배포가 만들어집니다. 둘은 별개 목록입니다.
08

GitHub Repository Secrets 환경 변수에 clasp 로컬 인증 토큰 정보(.clasprc.json 파일 데이터)를 보안 자격 증명으로 등록합니다.

확인 GitHub 시크릿에 CLASPRC_JSON 이 등록되고 워크플로에서 참조됩니다.
09

GitHub Actions 워크플로(.github/workflows/deploy.yml)를 구성하여 main 브랜치 Push 시 clasp push 및 deploy가 자동 수행되는 CI/CD 파이프라인을 구축합니다.

GitHub Actions 에서 clasp 를 쓰려면 ~/.clasprc.json 을 시크릿에서 복원해야 합니다.

확인 main 머지 시 Actions 가 실행되어 push·deploy 가 자동 수행됩니다.

확인 방법 최종 결과 2개

소스 코드 변경 커밋 3회가 모두 CI/CD 로 자동 빌드·배포되어 성공률이 100%입니다.

이전 버전을 재배포하면 롤백이 정상 동작합니다.

자주 겪는 오류

clasp clone 이 403 으로 실패
Apps Script API 가 꺼져 있습니다. script.google.com/home/usersettings 에서 켜세요. clasp login 은 성공하기 때문에 원인을 인증에서 찾다가 시간을 버리는 지점입니다.
push 했는데 편집기에 반영 안 됨
rootDir 밖에 파일을 만들었을 가능성이 큽니다. .clasp.json 의 rootDir 아래에 있는 파일만 업로드됩니다. clasp status 로 대상 파일을 확인하세요.
GitHub Actions 에서 인증 실패
~/.clasprc.json 이 없거나 형식이 깨진 경우입니다. 로컬의 해당 파일 전체 내용을 시크릿에 넣어야 하며, 줄바꿈이 보존되는지 확인하세요.
배포는 됐는데 롤백이 안 됨
clasp version 으로 버전을 만들지 않고 배포했기 때문입니다. deploy 는 버전을 가리키는 포인터라, 가리킬 버전이 없으면 되돌릴 수 없습니다.
배포할 때마다 URL 이 바뀜
새 배포를 만들면 새 ID 와 URL 이 생깁니다. 운영 URL 을 유지하려면 clasp deploy -i <배포ID> 로 기존 배포를 갱신해야 합니다.
clasp push 가 로컬 변경을 덮어씀
push 는 로컬 → 서버 방향입니다. 편집기에서 직접 고친 내용은 사라집니다. 팀 작업에서는 편집기 직접 수정을 금지하는 규칙이 필요합니다.
